# Lakshmikant Deshpande personal site

A personal site about my work as a software engineer and the things I build.
Warm paper, a single muted accent, locally hosted type, and an open editorial
layout. Built with Eleventy, Markdown, and plain CSS.

## Run locally

Requires Node.js 22 or newer.

```sh
npm ci
npm run dev
```

Open http://localhost:8080. Changes to source files refresh the preview.

```sh
npm run check    # clean production build, link and metadata checks
npm run build    # static files in _site/
```

The output can be served by any static host. There is no application server,
analytics, remote font request, feed, browser framework, or client-side
JavaScript.

## Edit the site

Navigation is About, Posts, and Contact.

- `src/index.njk`: homepage introduction, open career timeline with links to the
  company write-ups, the Programmer Cat feature, and the latest posts.
- `src/about.njk`: the personal page (interests, approach, education, contact).
- `src/experience/*.md`: short write-ups on what I worked on at each company.
- `src/posts/index.njk`: the posts index.
- `src/posts/*.md`: published posts (see below).
- `src/_includes/icons/`: company marks and social icons.
- `src/assets/styles.css`: colours, typography, and responsive rules.
- `src/assets/social-card.png`: the 1200×630 Open Graph preview image.
- `src/_data/site.js`: name, email, social links, and canonical site URL.
- `src/_includes/layouts/`: shared site, experience, and post templates.

The homepage introduces the person first and links once to Programmer Cat, the
other personal website. The apps themselves live on programmercat.com.

Public copy is grounded in the resume and existing project descriptions.
Employer-specific metrics, internal project details, phone number, private family
details, and unsupported claims are omitted. The full resume is not in this
repository or the site.

The social card is generated from the site type and palette and regenerated by
hand when the name or role line changes; keep its Open Graph alt text in
`src/_includes/layouts/base.njk` in step.

## Publish posts

The Posts page has an intentional empty state until there is a real post.
A starter draft lives in `content-drafts/first-note.md`, outside the generated
site. No invented posts are presented as previously published work.

Add a Markdown file under `src/posts/`, for example `my-first-note.md`:

```yaml
---
title: My first note
description: A short description of what this post is about.
date: 2026-10-04
category: Building
draft: false
---
Your post goes here. Markdown headings, links, lists, code blocks, and images work.
```

Set the date to the real publication date. A post is served at `/posts/<file-slug>/`.
`draft: true` suppresses the output page, the posts list, the homepage list, and the
sitemap. Draft previews are not built; to preview one, set `draft: false` locally and
restore it before publishing. After moving a post or changing its status,
`npm run build` removes stale output files. Posts appear newest first on the Posts
page and on the homepage.

## GitHub Pages

The included Actions workflow builds and checks the site, then deploys `_site/`
when changes reach `master`, or when manually dispatched from GitHub.

Before the first deployment, set repository **Settings → Pages → Source** to
**GitHub Actions**. Merge this branch into `master` only when ready to publish.
The build defaults to `https://lakshmikantdeshpande.github.io` for canonical URLs.

### Custom domain cutover (separate from implementation)

`ldeshpande.com` currently serves the Peerlist profile. This change does not alter
DNS, that profile, or GitHub's domain settings.

When ready to replace it:

1. Verify the custom domain in GitHub and follow GitHub Pages' DNS instructions.
2. Set the Pages custom domain to the chosen canonical hostname and enable HTTPS.
3. Set the repository Actions variable `SITE_URL` to that hostname with `https://`.
4. Redeploy and check the apex/www redirect, canonical tags, sitemap, and HTTPS.

Do not point DNS at a local development server. There is intentionally no `CNAME`
file in this preview branch.

## Checks and limits

`npm run check` checks internal links and anchors, generated page metadata, unique
IDs, font assets, draft exclusion, and the expected output files. It also asserts
there is no feed output, no `/writing/` links, and no project-notes output.

At implementation time, `npm audit` reports an upstream `braces` denial-of-service
advisory through Eleventy's development file-watching dependencies. The stable
Eleventy release does not yet supply a supported fix; do not apply the suggested
major-version downgrade. These dependencies run only in local/CI builds and are
not shipped to the static site. Recheck upstream when upgrading Eleventy.

Fonts are DM Sans and Instrument Serif, hosted locally under their SIL Open Font
Licenses. License files are included under `src/assets/fonts/`.
